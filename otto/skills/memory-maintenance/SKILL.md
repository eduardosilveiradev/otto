## Memory maintenance

- **Hygiene, nightly at 05:00 (after consolidation), no model call.** `otto/hygiene.ts` closes only what the evidence closes and writes why on the loop (`closedReason`, `closedBy:"hygiene"`): an auto-filed `crash loop:` note for a reverted install closes once no crash has recurred for `hygiene.crashQuietDays` (default 14) in `access.json` (one that filed a failing test is only proposed, or closed once that test file is gone), exact duplicates close, and everything merely old is proposed once with buttons, never closed. A loop whose due date has slid later three times gets that pattern named once, ever. "What did you close?" → `loop_hygiene(recent:true)`; undo is `remember(id, status:"open")`, after which the pass never touches that loop again. Nothing is deleted.
- **Memory review, nightly after consolidation.** `otto/memreview.ts`: a read-only session plans merges of duplicate memories, rewrites of vague ones and removals; the channel applies at most 30, repoints `[[links]]` and MEMORY.md lines, and refuses any change that drops a date, a quoted phrase or a Why / How to apply line. Before the first write it tars every memory dir to `~/.otto/memory-backups/memory-<day>.tar.gz` (14 nights kept) and appends what moved to `review-<day>.md` beside it. "What changed last night?" → read that log. "Undo last night's memory pass" → `tar -xzf ~/.otto/memory-backups/memory-<day>.tar.gz -C ~` (memories written since stay), or undo one entry by hand from the log. `bun otto/memreview.ts --dry-run` still runs the planning session (minutes, model quota) but changes no memory.
- **Memory audit.** Every `recall` with words in it logs a miss when nothing came back and counts each memory it returned (`recall-stats.json`). `memory_audit` lists never-returned and stale memories and the unresolved misses — evidence for a conversation, never a reason to message. Feedback memories (global) are compiled nightly into one deduplicated `house-rules` memory; `recall` it, or `memory_audit(section:"house_rules")`.
- **Memory diet, monthly on the 1st.** The channel measures what CLAUDE.md and the project MEMORY.md cost every session (roughly chars/4). From recall stats it proposes dropping the index lines of memories nothing has recalled, whose files stay searchable, and deleting memories that a newer one saying the same thing replaced. That is one message with [view diff], and the diff opens as an approval in the app. Nothing changes without Approve; declined or ignored items never come back; the undo is in `capability_log`. Don't raise it yourself or trim memory by hand on its account.
- **Rulebook.** `rulebook` lists every rule they have given you (feedback memories, global and project) by topic, with its file, date and the last time recall returned it; 60+ days unreturned is stale. Delete or edit only when they ask: each logs its inverse, so "undo that" is `revert_capability`. On the 22nd–24th from 10:00 the channel sends one count with [review] when something is stale; the tap shows the rulebook card with delete buttons, handled in the channel. Don't raise it yourself.
